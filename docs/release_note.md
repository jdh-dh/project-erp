# 릴리즈 노트 (release_note.md)

## v0.5.0 — Phase 5 릴리즈 이력/보고서/비용 (2026-07-08)

Phase 1~5 전체 완료. CLAUDE.md의 최종 목표(프로젝트/일정/하드웨어/소프트웨어/시험/문서/버전/이슈/산출물/보고서를 하나의 ERP에서 프로젝트 중심으로 관리)를 충족하는 첫 번째 전체 기능 버전.

### 신규 기능

**릴리즈 이력**
- 프로젝트별 릴리즈 등록·수정·논리 삭제 (버전, 제목, 릴리즈일, 내용)
- 프로젝트 내 릴리즈 버전 중복 방지, 등록자 자동 기록

**프로젝트 보고서**
- 종합 보고서 API·화면 (/projects/:id/report): 기본 정보, 일정 현황(진척률·지연), 이슈 상태별 통계, 시험 최근 결과 통계, HW/SW/릴리즈 현황, 비용 합계
- 저장 없이 조회 시점 실시간 집계, 인쇄 버튼 제공

**프로젝트 비용 (기본 수준)**
- 비용 항목 등록 (인건비/자재비/외주비/장비비/기타, 금액 > 0 검증)
- 총액·분류별 합계 집계 (비활성 제외)

### 시험 결과

- 백엔드 pytest 76건 통과 (신규 7건), 커버리지 94%
- E2E 수동 검증 완료 (검증 문서 참조)

## v0.4.0 — Phase 4 시험/이슈/문서 관리 (2026-07-08)

### 신규 기능

**시험 관리**
- 시험 케이스 등록·수정·논리 삭제 (단위/통합/현장 유형, 기대 결과)
- 실행 결과 기록 (PASS/FAIL/BLOCKED, 시험자 자동 기록, 비고) — member도 기록 가능
- 케이스별 최근 실행 결과 표시 (검증 결과 확인)

**이슈 관리**
- 이슈 등록 (버그/개선/고객요청/장애, 심각도 4단계) — 모든 사용자 등록 가능, 등록자 자동 기록
- 상태 관리: 접수 → 처리중 → 해결 → 종료 (해결 상태에서 재오픈 가능)
- 해결 처리 시 조치 결과 필수 입력·해결일 자동 기록, 원인 분석 기록
- 수정 권한: 관리자/매니저/담당자

**문서 관리**
- 문서 등록 (요구사항/설계서/인터페이스/시험계획서/검증문서/릴리즈노트/기타)
- 문서 버전·링크 URL 관리, 작성자 자동 기록, 변경 이력

**UI**
- 프로젝트 상세에 시험/이슈/문서 섹션 — 케이스·이슈 펼침 상세, 인라인 결과 기록·버전 수정

### 시험 결과

- 백엔드 pytest 69건 통과 (신규 9건), 커버리지 94%
- E2E 수동 검증 완료 (검증 문서 참조)

### 알려진 제한

- 문서 파일 업로드 미지원 (링크 방식) — 확인 필요

## v0.3.0 — Phase 3 하드웨어/소프트웨어 관리 (2026-07-08)

### 신규 기능

**하드웨어 관리**
- 보드 등록·수정·논리 삭제 (이름+리비전 조합 중복 방지, 회로/PCB 변경은 새 리비전으로)
- 보드 상태: 설계 → 시제 → 양산 / 단종
- BOM 부품 관리 (부품명, 부품번호, 제조사, 수량, 위치기호) — 보드 삭제 시 연쇄 비활성화
- 제작 이력 (제작일, 수량, 제작처, 결과)

**소프트웨어 관리**
- 모듈 등록·수정·논리 삭제 (펌웨어/앱/서버/라이브러리, 이름 중복 방지)
- GitHub 연동 1단계: 모듈 저장소 URL, 빌드 커밋 해시 기록
- 버전 관리 (모듈 내 중복 방지), 릴리즈 처리 시 릴리즈일 자동 기록
- 빌드 이력 (빌드 번호, 커밋 해시, 성공/실패), 배포 이력 (DEV/STAGE/PROD/FIELD)

**UI**
- 프로젝트 상세에 하드웨어/소프트웨어 섹션 — 보드→BOM·제작 이력, 모듈→버전→빌드·배포 계층 펼침

### 시험 결과

- 백엔드 pytest 60건 통과 (신규 12건), 커버리지 93%
- E2E 수동 검증 완료 (검증 문서 참조)

### 알려진 제한

- GitHub API 실연동(자동 커밋/릴리즈 조회) 미포함 — 확인 필요

## v0.2.0 — Phase 2 일정 관리 (2026-07-07)

### 신규 기능

**WBS**
- 프로젝트별 WBS 항목 등록·수정·논리 삭제 (하위 항목 연쇄 삭제)
- 계층 구조(상위/하위) — 자기 자신·순환 참조 차단
- 담당자, 계획 기간, 진척률(0~100), 상태(대기/진행/완료)
- 진척률 100% 입력 시 자동 완료 처리
- 종료일 경과 미완료 항목 자동 '지연' 판정
- 기간 변경 등 모든 변경은 change_logs에 기록 (일정 변경 이력)
- 담당자 본인(member)은 자기 항목의 진척률·상태만 수정 가능

**마일스톤**
- 등록·수정·논리 삭제, 달성 처리(달성일 기록)
- 목표일 경과 미달성 시 '지연' 표시

**일정 요약**
- 프로젝트 전체 진척률(활성 WBS 평균), WBS/마일스톤 지연 건수 API

**UI**
- 프로젝트 상세에 일정 섹션 추가: WBS 계층 표시, 진척률 인라인 수정, 지연 배지, 마일스톤 달성 처리

### 시험 결과

- 백엔드 pytest 48건 통과 (신규 12건), 커버리지 93%
- E2E 수동 검증 완료 (검증 문서 참조)

## v0.1.0 — Phase 1 (2026-07-07)

### 신규 기능

**인증/사용자**
- JWT 로그인 (Access 30분 / Refresh 14일), 토큰 재발급
- bcrypt 비밀번호 해시
- 역할 기반 접근 제어 (admin / manager / member)
- 사용자 등록·수정·비활성화 (admin)

**고객사 관리**
- 고객사 등록·조회·수정·비활성화 (논리 삭제)
- 고객사 담당자 복수 등록·수정
- 고객사명 검색

**프로젝트 관리**
- 프로젝트 등록·조회·수정 (코드 중복 방지)
- 프로젝트 유형 (HW / SW / HYBRID)
- 상태 관리 및 전이 규칙 (준비→진행→보류/완료/취소)
- 참여자 지정, 계약 정보 등록·수정

**공통**
- 변경 이력(change_logs) 자동 기록 — 누가/언제/무엇을 (before/after JSONB)
- 요청 로깅, 공통 예외 처리
- 초기 admin 계정 생성 스크립트

### 기술 구성

- Backend: FastAPI + SQLAlchemy 2 + Alembic + PostgreSQL 16
- Frontend: React 18 + TypeScript + Vite + TanStack Query
- 배포: docker-compose (db / backend / frontend+nginx)
- CI: GitHub Actions (백엔드 pytest + 프론트 빌드/테스트)

### 시험 결과

- 백엔드 pytest 36건 통과, 커버리지 93%
- 프론트 빌드(타입 검사) 및 Vitest 통과
- E2E 수동 검증 완료 (검증 문서 참조)

### 알려진 제한

- 로그인 실패 횟수 제한 없음 (확인 필요)
- Phase 2(WBS/마일스톤) 이후 기능 미포함
